Não criar componentes que contrariem essas diretrizes.

---

# Regras Gerais

1. Nunca remover arquivos sem autorização explícita.

2. Nunca alterar mais de uma feature por vez.

3. Sempre manter compatibilidade com regras de negócio.

4. Sempre preservar responsividade.

5. Sempre preservar funcionamento do Firebase.

6. Sempre utilizar componentes reutilizáveis quando possível.

7. Nunca gerar dados mockados em produção.

8. Nunca substituir implementações funcionando por versões simplificadas.

9. Toda alteração deve ser incremental.

10. Antes de alterar uma feature existente:

* analisar impacto
* explicar impacto
* só então implementar
